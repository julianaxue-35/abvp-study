Animal ID, Tracking & Statistics

Animal ID, Tracking & Statistics · Shelter Management (18%) · Shelter Medicine

Skeleton summary of the Animal ID, Tracking & Intake/Outcome Statistics subdomain — fill from your notes; pre-filled high-yield points marked +.

The ID Mandate

  • Every animal needs a unique + individual ID and record, established at or prior to admission; "unknown" is a valid field entry, a blank field is a compliance failure+
  • Unique = no two animals share an ID; Individual = a litter needs one file per kitten, never one "Litter 404B" record
  • ID cannot be deferred until after sorting / treatment / housing assignment — care given before an ID exists is untraceable
Top trap "Unknown" is compliant; a blank field is not (blank implies data never collected = worse failure). Duplicate IDs make outbreak tracing impossible.

The Animal Record

  • 9 Phase-A intake items (ID · intake type · intake date · species · age · sex · spay-neuter status · description · weight/BCS) — weight/BCS (Body Condition Score) most commonly omitted; ID triad = photo + microchip scan result + identifying markings+
  • Sex and spay-neuter status are separate items (not one combined field); age cutoff <5 mo = pediatric (SAC)
  • Phase C history (5): medical · behavioural · people/animals lived-with · home environment · vaccine hx (rabies named specifically)
  • Triad legally binds animal to its digital record; identifying markings = scars · brands · tattoos · asymmetric coat patterns
Trap Microchip field = scan RESULT (chip number, or "no chip detected"), not "chip unknown". Dropping intake photos to save storage = explicitly non-compliant (photo is a mandated triad item).

Microchip Standards & Scanning

  • ISO 11784/11785 (International Organization for Standardization) = 15-digit, 134.2 kHz, passive RFID; universal scanner + two-pass (head-to-tail, tail-to-head) scan before recording "no chip detected"+
  • Legacy North American chip = 9/10-digit, 125 kHz; 15-digit ISO = country code (3) + ID (12), US code typ. 985 or 900
  • Format ≠ size — ISO vs legacy chips can be physically identical (12 mm×2 mm); difference shows only on scanner readout. Chips migrate from the shoulder-blade site
  • Chip found but not in a registry → search multiple registries (AAHA lookup, Found Animals, PetLink, HomeAgain, 24PetWatch); none is comprehensive
Trap A 125 kHz-only (non-ISO) scanner systematically misses ISO 134.2 kHz chips = false-negative "unchipped" = compliance failure. Universal scanners are not optional.

Physical ID Methods (In-Shelter Tools)

  • Dual ID — microchip (permanent, binds animal to digital record) + collar/cage-card (real-time visual ID for daily care); the cage card stays with the cage, not the animal → move it with every housing change+
  • Greatest ID-failure risk = card left behind on a housing move → move card WITH animal, confirm match, update digital location simultaneously
  • Collar/tag travels with the animal but never the sole ID; unsuitable for cats (escape risk)
  • Intake photo is static (won't show shaving/illness) → re-photograph long-stay animals

In-Shelter Tracking

  • Housing location by time is the single most critical tracking field — time-stamped location logs are what make infectious-disease contact tracing possible+
  • Three continuous in-shelter mandates: (1) medical findings/tx/procedures (2) behavioural findings/plans (3) housing locations by time
  • Housing log = start/end date+time per location; off-site counts too (foster, adoption events, transport)
Trap Rabies vaccination hx is the one vaccine item called out by name (drives quarantine + bite-case law). Without time-stamped housing logs, outbreak contact tracing is impossible → shelter-wide quarantine.

Outcome Documentation

  • Two fields close a record: outcome type + date of outcome — both required; one without the other = incomplete
  • Outcome date drives ALOS; outcome type drives LRR + Asilomar category reporting
  • Exact calendar date required ("5 Mar 2026", not "early March")
  • Outcome types span adoption · RTO · transfer · RTF · foster · euthanasia · died-in-care · lost-in-care

SAC Intake Categories

  • 6 intake types: stray/at-large · owner surrender · OIE · transfer in · return · born in care
  • Return = original record reopened, not a new record; born-in-care = own record from birth
  • Stray = subject to legal hold before disposition; owner surrender = no stray hold (signs relinquishment)
Trap OIE (Owner-Intended Euthanasia) is its own SAC category, NOT owner surrender — bundling it overstates surrenders and distorts outcome stats.

SAC Outcome Categories

  • Live: adoption · return-to-owner (RTO) · transfer to rescue · return-to-field (RTF)
  • Non-live: died in care · lost in care · euthanasia · OIE performed
  • Euthanasia split into Asilomar Healthy / Treatable / Unhealthy-Untreatable for meaningful reporting
Trap Return-to-field (RTF) cats ARE admitted and counted in the SAC BasicDataMatrix — and count as a live outcome.

Key Performance Metrics

  • Live Release Rate (LRR) = live outcomes / total live intakes; Save Rate is the analogous Asilomar / Shelter Animals Count (SAC) measure — report both within Asilomar Healthy / Treatable / Unhealthy-Untreatable categories+
  • ALOS = Σ individual LOS / n; each LOS = outcome date − intake date; track by species/age/intake type/track
  • SAC BasicDataMatrix uses LRR Method 1 = live outcomes / total live intakes (3 methods exist)
  • Return rate = returned / total adopted; a high rate isn't inherently bad (return-friendly culture)
Trap Garbage in, garbage out — every metric is only as reliable as the individual records; approximated dates or inconsistent intake types corrupt all downstream stats.
